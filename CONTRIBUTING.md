# Contributing guidelines

## Developer guidelines

### Coding style

The coding style is defined in [.editorconfig](./.editorconfig) and [.clang-format](./clang-format). You may improve it by editing those files and then applying it to the whole repo.

### Licensing

To avoid (reduce) licensing headaches, this project tries to be [REUSE-compliant](https://reuse.software/tutorial/).

### Tooling

Recommanded tools to help with the guidelines above:
- [EditorConfig compatible editors](https://editorconfig.org/)
- [clang-format](https://clang.llvm.org/docs/ClangFormat.html)
- [reuse-tool](https://codeberg.org/fsfe/reuse-tool)

### Commits

Please try to make one commit per self-contained change. For example:

- add functionality XX
- fixes deprecation of YY
- bugfix for ...

Use [Signed-off-by trailers](https://git-scm.com/docs/SubmittingPatches#sign-off) and/or [cryptographic signatures](https://git-scm.com/book/ms/v2/Git-Tools-Signing-Your-Work) to improve traceability.

## Other types of contributions

You can help improve documentation by either creating it or opening issues about missing docs

You can open issues for new functionalities you would like to see added to wdisplays

You can report bugs or try to replicate bugs reported by others
